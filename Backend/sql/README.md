# Database (PostgreSQL + Alembic)

This project uses the SOP's **Option B – ORM-based setup**: SQLAlchemy models plus Alembic migrations.

| Folder | Purpose |
|---|---|
| `migrations/` | Alembic environment (`env.py`) and revision files in `versions/`. The single source of truth for schema changes. |
| `schema/` | `initial_schema.sql`, a read-only SQL snapshot generated from the migrations for reference. |
| `seeds/` | `sample_reports.json`, the dummy website reports loaded by `scripts/data/seed_reports.py`. |

## Tables

- `reports`: one row per generated report (`slug` is the public share key, unique).
- `report_pages`: the pages read for a report (`position` 1–5, title, meta description, headings as JSONB, summary and counts). Rows are removed automatically when their report is deleted (`ON DELETE CASCADE`).

## Common commands (run from `Backend/` with the virtual environment active)

```bash
alembic upgrade head                            # apply all migrations
alembic revision --autogenerate -m "describe"   # create a migration after changing models/db/*
alembic check                                   # confirm models and migrations are in sync
alembic downgrade -1                            # roll back the latest migration
alembic upgrade head --sql > sql/schema/initial_schema.sql   # refresh the SQL snapshot
```

The database URL comes from `DATABASE_URL` in `.env` (read through `config.py`); it is not stored in `alembic.ini`.

## Rules

- Change the schema only through a new migration; never edit a migration that has already been applied elsewhere.
- Review autogenerated migrations before committing them.
- Keep model files (`models/db/`) and migrations in the same commit.
